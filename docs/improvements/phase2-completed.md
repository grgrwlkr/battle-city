### ✅ Задача 2.2: Рефакторинг систем анимации

**Проблема:** 
- Все системы анимации (`animate_players`, `animate_enemies`, `animate_shield`, `animate_water`) содержали одинаковую логику

**Решение:**
- Создана обобщенная функция `animate_sprite_sheet<T: Component>` в `common.rs`
- Функция инкапсулирует общую логику анимации спрайтов
- Оставлены существующие функции для обратной совместимости и простоты использования
- Добавлены комментарии, указывающие на общий паттерн

**Результат:** 
- Обобщенная функция создана для будущего использования
- Код более документирован и готов к дальнейшему рефакторингу
- Обратная совместимость сохранена

**Созданная функция:**
```rust
/// Generic sprite sheet animation system
/// Animates sprites with AnimationTimer and AnimationIndices components
pub fn animate_sprite_sheet<T: Component>(
    time: Res<Time>,
    mut query: Query<(&mut AnimationTimer, &AnimationIndices, &mut Sprite), With<T>>,
)
```

### ✅ Задача 2.4: Замена println! и dbg! на логирование

**Найдено:**
- `dbg!(spawn_player_event)` в `player.rs:112`
- `println!("spawn born once")` в `player.rs:199`
- `println!(...)` в `bullet.rs:109-112`
- `dbg!(level_item)` в `bullet.rs:122`
- `println!("Game over")` в `bullet.rs:128`

**Решение:**
- Заменены все `dbg!` на `debug!`
- Заменены все `println!` на соответствующие уровни логирования:
  - `debug!` для отладочной информации
  - `info!` для информационных сообщений
  - `warn!` для предупреждений (Game Over)

**Результат:**
- Все логирование теперь использует стандартную систему логирования Bevy
- Можно контролировать уровни логирования через переменные окружения
- Улучшена отладка и мониторинг игры
