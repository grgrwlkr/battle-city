# Руководство по логированию и отладке

**Дата создания:** 2024

---

## Уровни логирования Bevy

В проекте используются следующие уровни логирования согласно документации Bevy:

1. **`trace!`** - Очень детальная информация, обычно не нужна в production
   - Используется для отладки деталей (spawn animations, entity despawning)

2. **`debug!`** - Отладочная информация для разработчиков
   - Используется для отслеживания важных событий (выстрелы, коллизии, движения)

3. **`info!`** - Информационные сообщения о важных событиях
   - Используется для основных игровых событий (спавн, переходы уровней, состояния)

4. **`warn!`** - Предупреждения о потенциальных проблемах
   - Используется для важных событий, требующих внимания (уничтожение базы, игроков)

5. **`error!`** - Критические ошибки
   - Используется для критических событий (Game Over, критические сбои)

---

## Настройка уровней логирования

### Переменные окружения

Используйте переменную окружения `RUST_LOG` для контроля уровней логирования:

```bash
# Логировать все сообщения уровня info и выше
RUST_LOG=info cargo run

# Логировать все сообщения (очень подробно)
RUST_LOG=debug cargo run

# Логировать только ошибки и предупреждения
RUST_LOG=warn cargo run

# Логировать только для конкретного модуля
RUST_LOG=battle_city=debug cargo run

# Комбинация модулей
RUST_LOG=battle_city=debug,bevy=warn cargo run
```

### Уровни по умолчанию

Bevy использует следующие уровни по умолчанию:
- **Release mode**: `warn` (только предупреждения и ошибки)
- **Debug mode**: `info` (информация, предупреждения и ошибки)

## Логируемые события

### Игроки (Players)

#### Спавн и жизнь
- `info!` - Начало анимации спавна игрока с позицией и оставшимися жизнями
- `info!` - Спавн игрока с позицией и жизнями
- `debug!` - Создание события спавна после завершения анимации
- `trace!` - Анимация спавна, удаление сущностей

#### Стрельба
- `debug!` - Выстрел игрока с направлением и позицией

#### Защита
- `debug!` - Удаление щита после истечения таймера

### Враги (Enemies)

#### Спавн
- `info!` - Спавн врага с позицией и прогрессом уровня
- `trace!` - Отмены спавна (максимум врагов, слишком близко к другим)
- `trace!` - Спрайт индекс выбранного врага

#### AI и движение
- `debug!` - Выстрел врага с направлением и позицией
- `trace!` - Смена направления врага при коллизии
- `trace!` - Смена направления врага

#### Cleanup
- `info!` - Очистка всех врагов
- `trace!` - Удаление отдельных врагов

### Пули и коллизии (Bullets & Collisions)

#### Столкновения
- `info!` - Столкновение пули с объектом (тип пули, позиция)
- `info!` - Столкновение с элементами уровня (тип элемента, позиция)
- `error!` - Уничтожение базы (Game Over)
- `info!` - Уничтожение каменной стены
- `debug!` - Отскок от железной стены
- `debug!` - Столкновение с границей области

#### Уничтожение
- `info!` - Пуля игрока уничтожила врага
- `warn!` - Пуля врага попала в игрока (жизни)
- `info!` - Пуля заблокирована щитом игрока
- `error!` - Game Over (конец жизней)

#### Взрывы
- `trace!` - Создание взрыва (тип, позиция)

### Уровни (Levels)

#### Загрузка и переходы
- `info!` - Загрузка уровня из LDTK
- `info!` - Переход на следующий уровень (прогресс, очистка)
- `info!` - Завершение игры (все уровни пройдены)
- `trace!` - LDTK мир уже загружен

#### Cleanup
- `info!` - Очистка LDTK мира
- `debug!` - Очистка элементов уровня
- `trace!` - Удаление отдельных сущностей

### Состояния игры (Game States)

#### Переходы
- `info!` - Вход в состояние StartMenu
- `info!` - Вход в состояние Playing
- `warn!` - Вход в состояние GameOver
- `info!` - Начало игры с режимом мультиплеера
- `info!` - Переключение режима мультиплеера

#### Пауза
- `info!` - Пауза игры
- `info!` - Снятие с паузы

### Cleanup системы

#### Общее
- `debug!` - Очистка всех сущностей определенного типа (игроки, пули, взрывы, etc.)
- `trace!` - Удаление отдельных сущностей

## Примеры использования

### Базовый запуск с логированием

```bash
# Запуск с информационным логированием
RUST_LOG=info cargo run

# Запуск с детальным логированием для отладки
RUST_LOG=debug cargo run

# Запуск только с предупреждениями и ошибками
RUST_LOG=warn cargo run
```

### Отладка конкретных модулей

```bash
# Логирование только для модуля player
RUST_LOG=battle_city::player=debug cargo run

# Логирование для player и enemy
RUST_LOG=battle_city::player=debug,battle_city::enemy=debug cargo run

# Логирование для всех модулей battle_city на уровне debug, остальное warn
RUST_LOG=battle_city=debug,warn cargo run
```

### Сохранение логов в файл

```bash
# Сохранение всех логов в файл
RUST_LOG=debug cargo run 2>&1 | tee game.log

# Сохранение только важных событий
RUST_LOG=info cargo run 2>&1 | tee game-info.log
```

## Типичные сценарии отладки

### Отладка спавна игроков

```bash
RUST_LOG=battle_city::player=debug cargo run
```

Будут видны:
- Спавн анимации
- Создание игрока
- Изменение жизней

### Отладка AI врагов

```bash
RUST_LOG=battle_city::enemy=debug cargo run
```

Будут видны:
- Спавн врагов
- Выстрелы
- Смена направлений
- Коллизии

### Отладка коллизий

```bash
RUST_LOG=battle_city::bullet=debug cargo run
```

Будут видны:
- Все столкновения пуль
- Типы целей
- Результаты столкновений

### Отладка состояний игры

```bash
RUST_LOG=battle_city::ui=info cargo run
```

Будут видны:
- Переходы между состояниями
- Пауза/возобновление
- Переключение режимов

### Полная отладка

```bash
RUST_LOG=debug cargo run 2>&1 | tee full-debug.log
```

Все события будут логироваться для полной картины происходящего.

## Структура логов

Логи Bevy имеют следующий формат:

```
YYYY-MM-DDTHH:MM:SS.Z LEVEL module::path: message
```

Пример:
```
2025-12-06T23:54:31.837280Z  INFO battle_city::player: Starting spawn animation for Player 1 at position (0.0, 0.0, 0.0), remaining lives: 3
2025-12-06T23:54:33.123456Z DEBUG battle_city::enemy: Enemy firing bullet in direction Up from position (100.5, 200.3)
```

## Рекомендации

1. **Для обычной игры:** Используйте `RUST_LOG=info` или уровень по умолчанию
2. **Для отладки проблем:** Используйте `RUST_LOG=debug`
3. **Для профилирования:** Используйте `RUST_LOG=warn` чтобы минимизировать влияние логирования на производительность
4. **Для разработки новых фич:** Используйте `RUST_LOG=battle_city=debug` для фокусировки на вашем коде

## Известные места логирования

### Критические события (error)
- Уничтожение базы
- Game Over (конец жизней)

### Важные события (warn)
- Попадание пули в игрока
- Уничтожение базы

### Информационные события (info)
- Спавн игроков и врагов
- Переходы между уровнями
- Переходы состояний
- Уничтожение врагов
- Уничтожение стен

### Отладочные события (debug)
- Выстрелы
- Столкновения
- Очистка сущностей
- Блокирование щитом

### Детальные события (trace)
- Отдельные операции с сущностями
- Анимации
- Отмены спавна
