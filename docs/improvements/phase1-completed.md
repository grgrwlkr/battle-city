## Выполненные задачи

### ✅ Задача 1.1: Удалить дублирование систем

**Проблема:** В `main.rs` были дублированные системы, которые выполнялись дважды за кадр:
- `spawn_ldtk_entity`, `auto_spawn_players` (строки 87-90 и 99-102)
- `players_move`, `players_attack` (строки 91-94 и 103-106)
- `animate_players`, `animate_shield` (строки 95-98 и 107-110)
- `auto_spawn_enemies`, `animate_enemies` (несколько дублирований)
- `enemies_move`, `enemies_attack` (несколько дублирований)
- `move_bullet`, `handle_enemy_collision`, `pause_game` (несколько дублирований)

**Решение:**
- Удалены все дублированные регистрации систем
- Каждая система теперь регистрируется только один раз
- Все системы организованы в логические группы

**Результат:** Проект компилируется без ошибок, системы выполняются один раз за кадр

---

### ✅ Задача 1.2: Добавить SystemSets и явные зависимости

**Проблема:** Не было явного контроля порядка выполнения систем, что могло привести к неопределенному поведению.

**Решение:**

1. **Создан enum `GameplaySet` в `common.rs`** с логическими группами:
   - `Input` - обработка ввода
   - `Spawning` - спавн сущностей
   - `Movement` - движение
   - `Combat` - боевые действия
   - `BulletMovement` - движение пуль
   - `Collision` - обработка коллизий
   - `Effects` - эффекты после коллизий
   - `Animation` - анимации
   - `LevelManagement` - управление уровнями
   - `Ui` - пользовательский интерфейс

2. **Организованы системы в логическом порядке:**
   ```
   Spawning → Movement → Combat → BulletMovement → Collision → Effects → Animation
   ```

3. **Добавлены явные зависимости через `.after()`:**
   - `Movement` выполняется после `Spawning`
   - `Combat` выполняется после `Movement`
   - `BulletMovement` выполняется после `Combat`
   - `Collision` выполняется после `BulletMovement`
   - `Effects` выполняется после `Collision`
   - `Animation` выполняется после `Effects`
   - `LevelManagement` выполняется после `Collision`

**Результат:** Порядок выполнения систем теперь явно определен и документирован
