## Обзор анализа

Проект Battle City демонстрирует хорошее понимание ECS архитектуры Bevy и правильное использование основных концепций. Код организован модульно с четким разделением ответственности между модулями. Однако, есть несколько областей, где можно применить лучшие практики Bevy для улучшения производительности, читаемости и поддерживаемости кода.

## Сильные стороны проекта

✅ **Хорошая модульная структура**
- Четкое разделение на модули (player, enemy, bullet, level, ui)

✅ **Правильное использование ECS**

✅ **Event-driven архитектура**
- Использование событий для слабой связанности систем
- Правильная обработка событий коллизий

## Выявленные проблемы

### 🔴 Критические проблемы

#### 1. Дублирование систем в main.rs

**Проблема:** Одинаковые системы регистрируются дважды в `main.rs` (строки 87-110):

```rust
.add_systems(Update, (spawn_ldtk_entity, auto_spawn_players).run_if(in_state(AppState::Playing)))
.add_systems(Update, (players_move, players_attack).run_if(in_state(AppState::Playing)))
.add_systems(Update, (animate_players, animate_shield).run_if(in_state(AppState::Playing)))
// ... те же системы повторяются снова
```

**Последствия:**
- Системы выполняются дважды за кадр
- Лишняя нагрузка на CPU
- Потенциальные баги из-за двойного выполнения

**Приоритет:** КРИТИЧЕСКИЙ

#### 2. Отсутствие явных зависимостей между системами

**Проблема:** Нет использования `.before()` / `.after()` для контроля порядка выполнения систем.

**Примеры проблемных мест:**
- `move_bullet` должна выполняться после `players_attack` и `enemies_attack`
- `handle_bullet_collision` должна выполняться после `move_bullet`
- `spawn_explosion` должна выполняться после обработки коллизий

**Последствия:**
- Неопределенное поведение при изменении порядка регистрации
- Потенциальные race conditions
- Сложность отладки

**Приоритет:** КРИТИЧЕСКИЙ

### 🟡 Важные проблемы

#### 3. Предупреждения Clippy

**Найдено:**
```
warning: very complex type used. Consider factoring parts into `type` definitions
warning: use of `default` to create a unit struct
```

**Приоритет:** ВЫСОКИЙ

#### 4. Отсутствие SystemSets для организации

**Проблема:** Системы не организованы в логические наборы.

**Текущее состояние:**
```rust
.add_systems(Update, (players_move, players_attack).run_if(...))
.add_systems(Update, (enemies_move, enemies_attack).run_if(...))
```

**Рекомендация:**
```rust
#[derive(SystemSet, Debug, Hash, PartialEq, Eq, Clone)]
enum GameplaySet {
    Input,
    Movement,
    Combat,
    Animation,
}
```

**Приоритет:** ВЫСОКИЙ

#### 5. Повторяющийся код в системах анимации

**Проблема:** Все системы анимации (`animate_players`, `animate_enemies`, `animate_shield`, `animate_water`, `animate_explosion`) содержат одинаковую логику:

```rust
timer.0.tick(time.delta());
if timer.0.just_finished() {
    if let Some(atlas) = &mut sprite.texture_atlas {
        atlas.index = if atlas.index == indices.last {
            indices.first
        } else {
            atlas.index + 1
        };
    }
}
```

**Приоритет:** СРЕДНИЙ

#### 6. Отсутствие тестов

**Проблема:** Нет unit тестов или integration тестов.

**Приоритет:** СРЕДНИЙ

#### 7. Неоптимальные Query паттерны

**Проблема:** Некоторые системы выполняют итерации по всем сущностям каждый кадр, даже когда это не требуется.

**Пример:**
```rust
pub fn auto_spawn_enemies(
    // ... проверяет все враги каждый кадр
    if q_enemies.into_iter().len() >= MAX_LIVE_ENEMIES as usize {
        return;
    }

```

**Рекомендация:** Использовать изменяемые фильтры (`Changed`) или события.

**Приоритет:** СРЕДНИЙ

#### 8. Hardcoded константы

**Проблема:** Все константы жестко зашиты в код.

**Рекомендация:** Вынести в конфигурационные ресурсы.

**Приоритет:** НИЗКИЙ

pub fn animate_sprite_sheet<T: Component>(
    time: Res<Time>,
    mut query: Query<(&mut AnimationTimer, &AnimationIndices, &mut Sprite), With<T>>,
) {
    for (mut timer, indices, mut sprite) in &mut query {
        timer.0.tick(time.delta());
        if timer.0.just_finished() {
            if let Some(atlas) = &mut sprite.texture_atlas {
                atlas.index = if atlas.index == indices.last {
                    indices.first
                } else {
                    atlas.index + 1

}
