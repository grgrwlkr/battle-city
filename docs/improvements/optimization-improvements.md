# Оптимизации производительности

**Дата создания:** 2024

---

## Выполненные оптимизации

### ✅ Оптимизация 1: Улучшение Query паттернов

#### 1.1 Замена `iter().len()` на более эффективные методы

**Изменения:**
- `q_enemies.iter().len() == 0` → `q_enemies.is_empty()` (более читаемо и эффективно)
- `q_ldtk_world.iter().len() > 0` → `!q_ldtk_world.is_empty()`
- Использование `any()` вместо полной итерации для проверки существования

**Файлы:**
- `src/level.rs`: `auto_switch_level`, `cleanup_ldtk_world`
- `src/enemy.rs`: `auto_spawn_enemies`

**Преимущества:**
- `is_empty()` может быть оптимизирован компилятором
- `any()` делает early exit при первом совпадении

#### 1.2 Оптимизация проверки существования игроков

**Изменения:**
```rust
// До:
let mut player1_exists = false;
let mut player2_exists = false;
for player in &q_players {
    if player.0 == 1 { player1_exists = true; }
    if player.0 == 2 { player2_exists = true; }
}

// После:
let player1_exists = q_players.iter().any(|player| player.0 == 1);
let player2_exists = q_players.iter().any(|player| player.0 == 2);
```

**Файлы:**
- `src/player.rs`: `auto_spawn_players`

**Преимущества:**
- Более короткий и читаемый код
- Early exit при первом совпадении

#### 1.3 Оптимизация проверок расстояний

**Изменения:**
```rust
// До: полная итерация с return в цикле
for enemy_pos in &q_enemies {
    if distance < threshold { return; }
}

// После: any() для early exit
let too_close = q_enemies.iter().any(|pos| distance < threshold);
if too_close { return; }
```

**Файлы:**
- `src/enemy.rs`: `auto_spawn_enemies`

**Преимущества:**
- Более функциональный стиль
- Early exit оптимизация

#### 1.4 Оптимизация проверок пустоты в системах врагов

**Изменения:**
- Добавлена проверка `is_empty()` перед `iter().any()` в `enemies_attack`
- Позволяет избежать итерации, когда нет игроков или level items

**Файлы:**
- `src/enemy.rs`: `enemies_attack`

**Преимущества:**
- Пропуск дорогостоящих итераций, когда коллекция пуста

### ✅ Оптимизация 2: Батчинг операций спавна

#### 2.1 Оптимизация спавна Tree сущностей

**Изменения:**
- Вынесена загрузка текстур и создание atlas за пределы цикла
- Предварительно вычисляется offset
- Создается вектор для батчинга спавна

**До:**
```rust
for entity in entities {
    let texture = load(); // Загружается каждый раз
    let atlas = create(); // Создается каждый раз
    commands.spawn(...);
}
```

**После:**
```rust
let texture = load(); // Один раз
let atlas = create(); // Один раз
let mut to_spawn = Vec::new();
for entity in entities {
    to_spawn.push(translation);
}
for translation in to_spawn {
    commands.spawn(/* использует общие texture и atlas */);
}
```

**Файлы:**
- `src/level.rs`: `spawn_ldtk_entity`

**Преимущества:**
- Меньше повторных загрузок ассетов
- Более эффективное использование памяти

### ✅ Оптимизация 3: Использование Added фильтров

#### 3.1 LDTK entity spawning

**Уже реализовано:**
- `spawn_ldtk_entity` использует `Added<EntityInstance>` фильтр
- Обрабатываются только новые сущности, добавленные в этом кадре

**Файлы:**
- `src/level.rs`: `spawn_ldtk_entity`

**Преимущества:**
- Система выполняется только когда появляются новые LDTK сущности
- Не обрабатывает уже существующие сущности каждый кадр

## Дополнительные рекомендации

### Будущие оптимизации

1. **Changed фильтры для анимаций:**
   - Системы анимации могут использовать `Changed<AnimationTimer>`
   - Однако это может быть излишне, так как таймеры обновляются каждый кадр

2. **ParallelCommands:**
   - Bevy 0.17 может автоматически параллелизовать команды
   - Явное использование `ParallelCommands` может не потребоваться

3. **Профилирование:**
   - Рекомендуется использовать `cargo flamegraph` или `tracing` для профилирования
   - Выявление реальных узких мест требует runtime анализа

4. **Кэширование вычислений:**
   - `level_translation_offset` вычисляется несколько раз
   - Можно кэшировать результат в ресурсе

## Метрики производительности

**До оптимизаций:**
- Проверка существования игроков: O(n) полная итерация
- Проверка расстояний: полная итерация с early return
- Спавн Tree: загрузка текстур в цикле

**После оптимизаций:**
- Проверка существования игроков: O(k) где k - первый найденный элемент
- Проверка расстояний: any() с early exit
- Спавн Tree: батчинг с общими ресурсами

---

## Примечания

Большинство систем в игре уже хорошо оптимизированы:
- Используются фильтры `Added` где необходимо
- Системы выполняются только в нужных состояниях
- Collision detection делегирован Rapier (высокопроизводительный движок)

Дальнейшие оптимизации требуют профилирования для выявления реальных узких мест.
